## 2. 为什么现在才讲

前 12 课你写的循环都是这样：

```rust
let mut count = 0;
for t in &tasks {
    if !t.done {
        count += 1;
    }
}
```

真实代码里更常见的是这样：

```rust
let count = tasks.iter().filter(|t| !t.done).count();
```

两个完全等价。但第二种在真实项目 `cpe-test` 里出现的频率是：

| 写法 | 出现次数 |
|---|---|
| `.iter()` | 841 |
| `.map(` | 609 |
| `.collect()` | 329 |
| `.filter(` | 236 |

**不认识这些写法，那份代码你一行都读不下去。**

## 3. 闭包：没名字的函数

```rust
fn is_done(t: &Task) -> bool { t.done }   // 函数
let is_done = |t: &Task| t.done;          // 闭包，一回事
```

`|参数| 函数体`。参数类型几乎总是能省掉，因为编译器从上下文推得出来。

「闭」在哪？**它能抓住外面的变量**：

```rust
let keyword = "所有权";
let matches = |t: &Task| t.title.contains(keyword);   // ← 用了外面的 keyword
```

函数做不到这件事。函数只能用参数和全局的东西。

## 4. 七个最常用的

假设 `tasks: Vec<Task>`：

```rust
tasks.iter().count()                                  // 有几条
tasks.iter().filter(|t| !t.done).count()              // 有几条没做完
tasks.iter().map(|t| t.title.clone()).collect::<Vec<_>>()  // 标题列表
tasks.iter().find(|t| !t.done)                        // 第一条没做完的 → Option
tasks.iter().any(|t| !t.done)                         // 有没有没做完的 → bool
tasks.iter().all(|t| t.done)                          // 是不是全做完了 → bool
tasks.iter().map(|t| t.title.len()).sum::<usize>()    // 加起来
```

读法是**从左往右**：「拿到每一条 → 只留没做完的 → 数一数」。

`iter()` / `iter_mut()` / `into_iter()` 的区别，就是第 06 课那三种：

| | 给你什么 | 原来的列表 |
|---|---|---|
| `.iter()` | `&T` 借用 | 还能用 |
| `.iter_mut()` | `&mut T` 可变借用 | 还能用，而且被你改了 |
| `.into_iter()` | `T` 所有权 | **被吃掉了** |

## 5. 两个必踩的坑

### 坑一：迭代器是懒的

```rust
tasks.iter().map(|t| println!("{}", t.title));   // 什么都不会发生
```

没有 `collect()` / `count()` / `sum()` / `for_each()` 这类「要结果」的动作，
它**根本不动**。clippy 会警告你这一行没用。

### 坑二：`map(|t| t.title)` 编译不过

```rust
tasks.iter().map(|t| t.title)     // ❌
tasks.iter().map(|t| t.title.clone())  // ✓
```

`t` 是 `&Task`，`t.title` 是**借来的** `String` —— 不能从借来的东西里搬走。
这就是第 06 课那条规矩，换了个地方出现。

报错值得读完：`cannot move out of ... which is behind a shared reference`。

## 6. `collect` 要你说清楚收成什么

```rust
let ids = tasks.iter().map(|t| t.id).collect();   // ❌ 收成什么？
```

两种写法任选：

```rust
let ids: Vec<u32> = tasks.iter().map(|t| t.id).collect();
let ids = tasks.iter().map(|t| t.id).collect::<Vec<u32>>();
```

那个 `::<>` 叫 turbofish，读代码时会经常见到。

## 7. 什么时候还是该写 for

迭代器不是越长越好。这两种情况写 `for` 更清楚：

- **要改原来的东西**：`for t in &mut tasks { t.done = true; }`
- **链子超过三节**：三节以上就该拆成两句，或者干脆写 `for`

> 写代码是给人读的。一行 `.iter().filter().map().rev().take(3).collect()`
> 炫技成分大于沟通。

## 10. 常见错误

```
error[E0282]: type annotations needed
```
→ `collect()` 不知道收成什么。加 `: Vec<...>` 或 turbofish。

```
error[E0507]: cannot move out of `t.title` which is behind a shared reference
```
→ 第 5 节坑二。加 `.clone()`。

```
warning: unused `Map` that must be used
```
→ 第 5 节坑一。迭代器是懒的，加个 `collect()` / `for_each()`。

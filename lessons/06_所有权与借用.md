# 第 06 课：所有权与借用

**这是 Rust 最特别的一课，也是前期最容易卡住的一课。慢一点没关系，可以拆成两天。**

**目标**：看懂 `move` / `&` / `&mut`，能自己修掉常见的借用错误。

## 1. 先跑实验

```bash
cargo run --example lesson06_ownership
```

## 2. 一句话规则

> 每份数据同时只有一个主人。主人没了，数据就被清理掉。

由此推出三种情况：

### 移动（move）—— 把主人换了

```rust
let a = String::from("学习 Rust");
let b = a;              // 主人从 a 换成 b
println!("{a}");        // 报错：a 已经不是主人了
```

### 借来读（`&`）—— 看一眼就还

```rust
fn print_title(title: &str) { }

let title = String::from("练习函数");
print_title(&title);
println!("{title}");    // 还能用，因为只是借出去看了看
```

### 借来改（`&mut`）—— 借去动一下

```rust
fn add_one(titles: &mut Vec<String>) {
    titles.push(String::from("新任务"));
}

add_one(&mut titles);
```

### 「改原件」和「造新件」是两件事

这一课的练习会反复考这个区分，先把两种签名的形状记住：

```rust
// 改原件：借来改，不返回东西
fn add_suffix(title: &mut String, suffix: &str) {
    title.push_str(suffix);     // 直接动传进来的那个
}

// 造新件：借来读，返回一个新的
fn upper(title: &str) -> String {
    title.to_uppercase()        // 原件一个字没动
}
```

**看签名就知道它会不会动你的数据** —— 这是 Rust 最实用的地方之一。
`&mut` 在参数上，调用处也得写 `&mut`，所以读调用代码时也一眼能看见。

### 这几个字符串方法要分清

| 方法 | 动不动原件 | 返回 |
|---|---|---|
| `s.push_str("x")` | **动** | 不返回 |
| `s.push('x')` | **动**（加一个字符） | 不返回 |
| `s.to_uppercase()` | 不动 | 新 `String` |
| `s.to_lowercase()` | 不动 | 新 `String` |
| `s.replace("a", "b")` | 不动 | 新 `String` |
| `s.trim()` | 不动 | `&str`（借原件的一段） |
| `s.clear()` | **动**（清空） | 不返回 |

规律：**名字像动词祈使句的（push / clear）改原件，
名字像 `to_xxx` / `replace` 的造新件。** 这是标准库通用的命名习惯。

### 切一段出来：`split_once` 和 `find`

```rust
let title = "学习 Rust 语法";

// 按第一个空格切成两半，切不到返回 None
if let Some((head, tail)) = title.split_once(' ') {
    println!("{head} | {tail}");    // 学习 | Rust 语法
}

// 只要位置
let pos = title.find(' ');          // Option<usize>
```

两个都返回 `Option`（第 08 课细讲）——因为**可能切不到**。
这正是 Rust 的做法：「找不到」写进类型里，逼你处理，
而不是返回一个 `-1` 让你自己记得判断。

## 3. 为什么整数不用管这些

```rust
let x = 5;
let y = x;
println!("{x}");    // 完全没问题
```

整数、`bool`、`f64` 这类固定大小的小类型是**复制**，不是移动。所以你前几课从没被这个规则烦过 —— 一碰到 `String` 和 `Vec` 就开始报错了。

## 4. 借用的两条限制

1. 同一时间，要么有**多个只读借用**，要么有**一个可写借用**，不能混
2. 借用不能比数据活得久

第 2 条现在遇不到。第 1 条会在你一边遍历一边修改时撞上：

```rust
for t in &tasks {          // 只读借用还在用
    tasks.push(...);       // 又要可写借用 → 报错
}
```

解决办法通常是：先在循环里记下要做什么，循环结束后再动手。

## 5. `.clone()` 到底能不能用

新手常听到「`clone` 不好」，然后卡在那里不敢写，
借用错误改半小时也改不对。**这个态度是错的。**

先说结论：

> **写不顺就先 `.clone()`，把程序跑通。** 回头再看要不要去掉。

理由很实在：

- 你现在的程序处理的是**几十条待办**，复制一个字符串的代价约等于 0
- `clone` 的代价是**可见**的 —— 它明晃晃写在那里，将来一搜就能找到
- 为了省一次 clone 把代码绕得没人看得懂，那才是真的亏

什么时候该停下来想一想：

| 情况 | 怎么办 |
|---|---|
| 在循环里 clone 一个很大的东西 | 想想能不能只 clone 一次，或者改成借用 |
| clone 完只是读一读就扔 | 多半该收 `&` |
| 你 clone 是因为「编译器不让我过」 | 先读懂那条报错。有时正确的修法是换个顺序 |

**能借就借，借不动就 clone，clone 不了再想别的。** 这个顺序对了就行。

## 6. 参数该写什么类型

这是所有权规则在日常写代码时唯一要做的决定。三个问题就够了：

```text
这个函数要不要改它？
  ├─ 要   → &mut T
  └─ 不要 → 要不要在函数结束后还留着它？
            ├─ 要（存进结构体、放进列表）→ T（收所有权）
            └─ 不要（读一读就完）        → &T
```

具体到最常见的几个类型，**左边永远优于右边**：

| 收这个 ✓ | 别收这个 ✗ | 为什么 |
|---|---|---|
| `&str` | `&String` | `&str` 能接 `String` 也能接字面量，适用面更大 |
| `&[String]` | `&Vec<String>` | `&[T]` 能接 `Vec`，也能接数组 |
| `String` | —— | 确实要拿走所有权时就大方收 |

```rust
fn render(titles: &[String]) { }     // 调用：render(&titles) —— Vec 自动变切片

fn shout(title: &str) -> String { }  // 调用：shout(&s) 或 shout("字面量") 都行
```

收 `&str` 的那个函数，调用方是 `String` 还是字面量都行；
收 `&String` 的话，字面量就传不进来了 —— 白白少了一半的调用方。

> **参数收得越宽松，函数越好用。**

## 7. 一个现在还碰不到、但迟早会撞上的

返回借用的时候，编译器会开始问「这个借用能活多久」：

```rust
fn first_word(s: &str) -> &str { }   // 这个没问题，返回的借用来自参数 s
```

等你写出「返回值可能来自两个不同参数」那种函数，就会看到：

```
error[E0106]: missing lifetime specifier
```

那叫**生命周期**，写法是 `<'a>`。**这一课不用学它** ——
知道这个报错长什么样、知道它叫什么就够了，
真撞上的时候多半是函数设计得太绕，换个写法（比如返回 `String`）就没事了。

## 8. 为什么 Rust 要这么麻烦

用别的语言写代码，下面三类 bug 是家常便饭：

- 数据已经被释放了还在用它（崩溃，而且经常是在别处崩）
- 两个线程同时改同一份数据（结果随机，最难查的一类）
- 忘了释放，内存越吃越多

**这三类在 Rust 里全是编译错误。** 你现在多花的这几天，
换的是以后不用在半夜查一个「只在生产环境出现、复现不了」的崩溃。

而且它**不靠垃圾回收**做到这件事 —— 没有 GC 停顿，
所以 Rust 能写操作系统内核，也能写你后面要读的那个测试工具。

> 所有权不是 Rust 加给你的负担，是它拿掉 GC 之后必须先跟你讲清楚的那件事。

## 11. 常见错误对照表

| 报错 | 原因 | 怎么修 |
|---|---|---|
| `borrow of moved value` | 数据被移走了还在用 | 传参加 `&`，或者 `.clone()` |
| `cannot borrow as mutable` | 变量没写 `mut` | `let mut x = ...` |
| `cannot borrow as mutable more than once` | 同时借了两次可写 | 拆开，别同时借 |
| `expected &str, found String` | 类型对不上 | 传 `&s` 或 `s.as_str()` |

**一个不报错但结果不对的：** 调了 `title.to_uppercase()` 却没接返回值，
原件一个字没变。那种方法**不动原件** —— 见第 2 节那张表。

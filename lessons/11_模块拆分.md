# 第 11 课：拆分模块

**目标**：`main.rs` 已经两三百行了，把它拆成几个各管一摊的文件。

## 1. 先跑实验

```bash
cargo run --example lesson11_modules
```

## 2. 怎么拆

按"职责"拆，不按"大小"拆。这个程序天然分三块：

| 文件 | 管什么 |
|---|---|
| `model.rs` | 数据长什么样（`Task`） |
| `store.rs` | 对数据做什么（增删改查、存盘） |
| `view.rs` | 怎么显示给人看 |
| `lib.rs` | 把它们串起来，对外提供 `run()` |
| `main.rs` | 只剩：读参数 → 调 `run()` → 显示结果 |

## 3. 语法

`src/lib.rs`：

```rust
pub mod model;
pub mod store;
pub mod view;

pub fn run(args: &[String]) -> Result<String, String> { ... }
```

`src/main.rs`：

```rust
use rust_starter::run;      // 注意：用的是包名，中划线变下划线

fn main() {
    match run(&args) { ... }
}
```

`src/store.rs` 里引用别的模块：

```rust
use crate::model::Task;     // crate = 本包的根
```

## 4. pub 的意义

不写 `pub` 的东西外面看不见。这不是麻烦，是好事：**没标 `pub` 的就是内部细节，你以后随便改都不会影响别人。**

```rust
pub fn add(...) { }         // 对外提供
fn next_id(...) { }         // 内部细节，外面用不了
```

struct 的字段也要单独标 `pub`：

```rust
pub struct Task {       // 类型对外可见
    pub id: u32,        // 字段也要一个个标
    pub title: String,
    done: bool,         // 不标就是私有，外面读不到也改不了
}
```

### 先别加 `pub`

惯例是**默认不加，等真有别处要用了再加**。

理由很实在：标了 `pub` 的东西就成了承诺，改它要考虑所有调用方；
没标的随时能改、能删、能改名，编译器会把所有受影响的地方指给你。

> **能私有就私有** —— 这不是洁癖，是给自己留改动的余地。

### 四种 `pub`

| 写法 | 谁能看见 |
|---|---|
| （不写） | 只有本模块和它的子模块 |
| `pub` | 谁都能看见 |
| `pub(crate)` | 只有**本包**能看见，包外看不见 |
| `pub(super)` | 只有父模块能看见 |

`pub(crate)` 在真实项目里很常见：一个函数要跨模块用，
但不想让它成为对外 API 的一部分。
（`cpe-mini` 对照的真实项目里到处是 `pub(super)`，现在认个脸。）

## 5. 路径怎么写

```rust
use crate::model::Task;    // crate = 本包的根，从顶上开始找
use super::Task;           // super = 上一层模块
use self::helper::x;       // self = 当前模块
```

三个里最常用的是 `crate::` —— 从根开始写，不管文件挪到哪都不会错。

一次引入多个：

```rust
use crate::model::{Task, Priority};
use std::collections::{HashMap, BTreeMap};
```

### 模块名就是文件名

```text
src/
├── lib.rs        ← 里面写 pub mod model;
├── model.rs      ← 这就是 model 模块
└── store.rs      ← 这就是 store 模块
```

`lib.rs` 里不写 `pub mod model;`，那个文件**根本不会被编译** ——
新建了 `.rs` 文件却提示 `unresolved module`，十有八九是漏了这一行。

## 6. 为什么要有 lib.rs

拆出 `lib.rs` 之后，业务逻辑就能被测试直接调用了（下一课要用）。`main.rs` 里的东西测试是够不着的。

这也是真实 Rust 项目的普遍做法：**`main.rs` 只做入口，业务在 `lib.rs` 那一侧。**

## 7. 动手任务

把 `src/main.rs` 拆成上面 5 个文件。

建议顺序：先建 `lib.rs` 和 `model.rs`，把 `Task` 搬过去，跑通 `cargo check`；再搬 `store`；最后搬 `view`。**每搬一步就 check 一次**，不要一次搬完再编译。

## 8. 验收

```bash
cargo run -- list
cargo run -- add "验证拆分后还能用"
cargo run -- list
```

- [ ] 功能和拆分前完全一样
- [ ] `main.rs` 少于 30 行
- [ ] `store.rs` 里至少有一个**不带 `pub`** 的内部函数
- [ ] 能说出为什么 `use rust_starter::run` 里是下划线而 `Cargo.toml` 里是中划线

## 9. 常见错误

```
error[E0603]: function `add` is private
```
→ 漏了 `pub`。

```
error[E0432]: unresolved import `crate::model`
```
→ `lib.rs` 里漏了 `pub mod model;`，或者文件名拼错了。
